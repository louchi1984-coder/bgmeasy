# 哼唱创作（分析模式的“保留”分支）

用户给了一段旋律（录音、口哨、清唱，音频或视频文件）时使用。目标是保留用户自己的旋律，音高和节奏是用户的创意内核，不要擅改。

先辨认哼唱提供的是短动机、完整主题还是较完整的曲段，不预设素材一定不完整。按用户目标保留核心、转写或扩展为 BGM；完整材料不为执行“发展”步骤而强行改写（G01/M06）。

## 步骤

1. **先问清（缺就问）。** 为转写确认要保留的哼唱乐句；拍点或音高有歧义时，再核对速度或调性。基于哼唱创作新 BGM 时，沿用 SKILL.md 步骤 1 的选样、成品时长和配器顺序。三个小样里主旋律保持一致，变的是编配、节奏和声部关系。
2. **转写。**
   ```bash
   python3 -I scripts/hum2score.py hum.m4a score.json --bpm 100
   ```
   示例速度为 100 BPM；已知调性或目标音色时可加 `--key "D major"` 或 `--inst erhu`。脚本把哼唱转写成 `motif` 段落，并写入 `design.motif`。终端会打印音准偏差、八度移位、bpm 来源、调性可信度、被吸附的音数和逐小节和弦。
3. **核对转写。** 调性可信度 <0.05 或 bpm 是估计的，就和用户确认后用 `--key`、`--bpm` 重跑。出调音被吸附时告诉用户，需要保留就加 `--no-snap`。成品先组织完整乐句（见 [melody-patterns.md](melody-patterns.md)），可原样呈示和重复，不强制先变形；`motif` 段落用于核对转写，用户明确要求原样保留的内容优先遵循。
4. **纳入全曲方案。** 选样并确定成品要求后进入 SKILL.md 的“规划全曲”，先规划已有材料在全长中的位置、前后连接和最终去向，再落实和声、节奏及配器。按 melody-patterns.md 选择必要的保持、回应或延续；完整材料可原样保留，不以变法数量证明发展，也不要求每条旋律都从同一动机派生（M06）。自动推断的和弦只作候选。
5. **渲染后对照哼唱试听。** 动机每次出现是否听得出来，是否被编配盖住。

## 局限

- 单声部干声最准，有伴奏或混响大会出错。
- 格子默认 16 分音符，三连音和自由节奏会被扭成直拍。
- 跨小节长音被拆成两个同音。
- 自动和弦只是近似。
- 需要 librosa。
