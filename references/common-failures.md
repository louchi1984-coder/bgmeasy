# 典型失误（全部来自用户的真实反馈）

写谱前先读一遍。症状是用户听到的，根因是我们做错的。

| 症状（用户原话/意思） | 根因 | 怎么避免 |
|---|---|---|
| “感觉像儿歌”（趾高气昂、轻松诙谐） | 木琴/钟琴/高音区拨弦 + 均匀八分 + “嘣嚓”低音 + 大调对称音型叠在一起 | 先问“轻松”偏成人、可爱还是活力；换成中低音区的铜管、钢琴、弱音小号，加切分和留白 |
| “没有武侠味，不厚重” | 音区偏高偏轻，缺低音底，节奏碎 | 压低音域，加真实低弦或大鼓，放慢并加半拍重击；中国风靠乐器与演奏，不只靠音阶 |
| “开始听不清，8 秒突然变大，13 秒后又小了” | 按数值追“段落对比”，把段落力度拉得太开 | 相邻段落变化小；先看每秒电平曲线再交付 |
| “要 10 秒，7 秒就没了；20 秒，16 秒就没了” | 结尾写成轻长音、尾音太长，验收还鼓励“越低越好” | 音乐铺满整段，结尾按设计完成；看有效时长 |
| “声音单薄，不像商业 BGM” | 只有旋律、琶音、pad、贝斯四层，和声排列单一 | 先设计每层职能，再决定加不加；不是凑层数；去掉贝斯反而更好时就去掉 |
| “原曲没有回落，你为什么要回落” | 把归一化能量曲线当真实起伏 | 先看每秒电平或自行测量电平范围（新的参考分析不输出 `level_range_db`）；范围小就别造起伏 |
| “为什么不用钢琴？合成器是配角” | 凭曲名联想选音色 | 标准乐器做主角，合成器做配角；音色选择要写依据 |
| “动机放进去太简单；成品里应该是发展后的” | 未结合需求和整句作用判断素材的呈示或发展 | 按需求决定呈示或发展；以 melody-patterns.md 为准，允许原样呈示和重复，不强制变形 |
| “模仿只学到参数” | 把分析结果改写成通用的“和弦循环 + 展开旋律” | 先分观测/推测；复现观测到的节奏分组、中心音、背景变化方式 |
| “有的 BGM 有高潮，有的没有” | 默认套“起推顶收” | 先判断走向类型，需求没说就按平稳型 |
| “和声范式有多种” | 同一首只用一条进行 | 多条候选里按需求选，并写出为什么不选另外几条 |

## 通用原则

- 听感优先于数值。检查脚本全绿，也可能不好听。
- 联想不是证据。曲名、风格词、上一首的做法，都不能直接当事实。
- 候选不是结论。分析算法给出的音符、和弦、结构都是待核对的候选。
- 层、音色、结构都要能回答“为什么需要”。
- 没听过就写“未核听”。
